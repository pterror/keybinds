- [x] Scroll (wheel) shortcuts. Scroll bindings now run once per step of scrolling (a notch, or 50px of trackpad deltas), hold the page still between steps, end a gesture after 200 ms idle, and both numbers are options.
- [x] Shifted punctuation bindings can never fire. Now any single character can be bound as itself and matches however it's typed (`?` fires on Shift+/), `shift+<symbol>` / `shift+<digit>` are normalized to the physical key (`shift+slash`, `shift+digit1`), and recording a shifted symbol stores the character.
- [x] `styles/palette.css` didn't cover `<keybind-settings>` and hard-coded dark colors. It now styles every component, selected by their `data-keybinds` kind, with all colors and fonts from `--keybinds-*` custom properties whose defaults follow the page's color scheme.
- [x] `formatKeyParts` showed code-name keys raw (`shift+slash` as "SLASH"). Physical key names now show as the character they type.
- [x] `<keybind-cheatsheet auto-trigger>` always held Control for 200 ms. It now holds `$mod` by default (Meta on Mac), and `trigger-key` / `trigger-delay` attributes choose the modifier and delay.
- [x] `dist/index.d.ts` was behind `src/index.js` and `build:types` failed on type errors; the four "failing" tests only failed because `node_modules/happy-dom` was a symlink into another repo's newer happy-dom, whose elements reject Bun's native events. The test setup now installs happy-dom's own DOM and event classes, so the suite passes on either version.
- [ ] `<keybinds-settings>` shows a "Release" switch on every binding, which makes the panel busy for something few people use (seen in cyoa). Consider showing it only for bindings that are releases, or behind a per-binding menu.
- [x] `BindingsStore` could only keep overrides in localStorage, so an app with its own state (or a server) had two copies of a person's bindings. It now takes any `BindingsStorage` (`load`, `save`, optional `subscribe` to follow changes made elsewhere); a string still means a localStorage key. `CommandHub` takes the same as `storage: (scope) => BindingsStorage`.
- [x] A binding only fired with exactly its modifiers, so a game's `w` stopped working while Shift was held for something else. Commands can now set `anyModifiers: true`: their bindings match whatever else is held (their own modifiers still required), with exact bindings still first.
- [x] A key held while the window lost focus never got its release (the keyup goes to whatever has focus), so holds stayed open. Held keys are now released on blur; held mouse buttons are checked against `MouseEvent.buttons` on the next mouse event instead, since they may still be down.
- [x] Held controls (a game's movement) had to be pieced together from press and release bindings. `keybinds()` now returns its cleanup with `held(id)`, and `CommandHub` has `held(id)`.
- [x] Gamepad buttons as triggers: `gamepad: ['a', 'rt:up']` on commands and schemas, rebindable in `<keybinds-settings>` (shown while a pad is connected), listed in the cheatsheet, `hub.gamepadFor(id)`. Pads are read each frame only while something binds a gamepad button and a pad is connected.
- [x] Axes: continuous inputs read every frame (`keybinds(..., { axes })`, `kb.axis(id)` → `{ position, delta }`), from mouse movement, sticks, triggers or key pairs, with a leading `-` to invert. Rebindable in the settings panel; `hub.setAxes`, `hub.axis`, `hub.axesFor`.
- [ ] The cheatsheet and palette don't list axes.
- [x] Everything was one 5,400-line file and `keybinds()` handled every kind of input in one closure, so a keyboard-only app shipped gamepad polling and axis code too. Each input (`keys()`, `mouse()`, `gamepad()`, `axes()`) is now its own module passed in as `inputs`; a binding no input reads is an error. Components and the hub are separate modules too, and the hub takes the component classes it should make. Keyboard-only `keybinds()` went from 5.1 KB to 3.6 KB gzipped.

- [x] `src/index.test.js` was one file covering every module, and a test could pass only because another registered a component first. Each module has its own test file now, importing only that module and `src/test-helpers.js`, and each passes run alone.

Formatting and recording are now each input's UI half (`keysUI()` in `keys-ui.js`, ...), which only the components need. The modal check named every component in a selector; components now carry `data-keybinds-modal` instead, which a page's own dialogs can use too. Keyboard-only `keybinds()` is 2.7 KB gzipped, from 3.6.
