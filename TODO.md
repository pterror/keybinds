- [ ] Scroll (wheel) shortcuts — e.g. `ctrl+scrollup` to switch tabs. The O(1) dispatch is trivial (add to `VALID_MOUSE`, listen on `wheel`), but wheel events are continuous, not discrete like clicks/keypresses. A single scroll gesture fires dozens of events with variable `deltaY` (trackpad smooth scrolling vs. mouse wheel notches), so commands need debouncing/throttling with tunable thresholds. Worth supporting because without it users lose schema integration, user remapping, cheatsheet display, and conflict detection — the actual value of the library. Needs a design that keeps the simple case simple (e.g. sensible default debounce) without over-configuring.
- [ ] Shifted punctuation bindings can never fire — `"shift+/"` parses fine (`/` is in `VALID_KEYS`) but a real keypress reports `key: "?"`, `code: "Slash"`, so the lookups are `shift+?` / `shift+slash` and never `shift+/`. Same for every shifted symbol and shifted digit (`shift+1` vs `key: "!"`, `code: "Digit1"`). Either normalize punctuation keys to their code names at parse time (`/` → `slash`) and emit `digitN` lookups, or reject `shift+<symbol>` in `parseKey` with a pointer to the code name. Found via pteraworld games (worked around there with `shift+slash`).

It also hard-codes dark colours, so it can't follow a host page's theme. Ship settings styles, and drive all component colours from CSS custom properties with fallbacks. Found via pteraworld games, which now ships its own themed stylesheet for all four components.
- [ ] `formatKeyParts` shows code-name keys raw: `shift+slash` renders as "SLASH" (and `$mod+Enter` as "↵" next to "Ctrl"). Code names need display glyphs (`slash` → `/`, `comma` → `,`, etc.).
